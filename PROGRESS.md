## Безопасность (требование владельца от 16.11.2026)

**Сделано:**
- **Шифрование диска (LUKS) — не делаю, решение владельца.** Код LUKS был написан и затем убран из `--from-iso`: btrfs без шифрования, как в исходном плане.
- **AppArmor — часть основной установки** (`38-apparmor.sh`): пакет `apparmor`, включённая `apparmor.service`, параметр ядра `lsm=landlock,lockdown,yama,integrity,apparmor,bpf`. Строка сверена с Arch Wiki (AppArmor#Installation) 16.11.2026. Загрузчик меняется по старому правилу: diff, копия `.bak`, правка только после ввода «да» (общие функции вынесены в `lib/bootloader.sh`). В `--from-iso` параметр сразу пишется в запись systemd-boot. Профили — штатные из пакета.
  - `apparmor.d` (roddhjav): в AUR есть `apparmor.d` 0.4916.0 и `apparmor.d-git`. Arch Wiki пишет, что проект пока не стабилен. Поэтому он ставится только по флагу `--apparmor-d`: просмотр PKGBUILD, затем ввод «да». Профили программ рабочего стола (Hyprland, hyprlock, hypridle, Quickshell, kitty, rofi, awww, matugen, SDDM, cliphist) переводятся в complain через `aa-complain`.
  - **firejail не добавлял.** Он есть в extra (0.9.82.2), но это setuid-root программа, у неё были уязвимости повышения привилегий. Вместе с AppArmor и без отдельной настройки под каждую программу пользы мало, а поверхность атаки растёт. Если понадобится песочница для браузера — лучше смотреть bubblewrap или Flatpak; это стоит решать отдельно.
- **Файрвол — nftables, а не ufw.** Почему:
  - nftables рекомендует Arch Wiki, на нём же работают iptables-nft и Docker;
  - ufw — надстройка над iptables, и порты Docker известным образом обходят его правила.

  Своя таблица `inet dots_firewall`: входящие запрещены, исходящие разрешены. Без `flush ruleset` и без цепочки forward, поэтому правила Docker не стираются, а контейнеры не ломаются. Порты Docker по умолчанию публикуются только на 127.0.0.1 (`"ip": "127.0.0.1"` в `/etc/docker/daemon.json`); наружу — только явным `-p 0.0.0.0:…`. Служба nftables включена.
- **Сеть.**
  - NetworkManager: `wifi.scan-rand-mac-address=yes`, `wifi.cloned-mac-address=stable`.
  - systemd-resolved: DNS-over-TLS на Quad9, `DNSOverTLS=yes`, `DNSSEC=allow-downgrade`, `Domains=~.`, пустой `FallbackDNS`. Сервер задаётся одной переменной `dns_servers` в `45-security.sh`.
  - NetworkManager с `dns=none`, чтобы DNS от роутера не шёл в обход TLS.
  - `/etc/resolv.conf` → stub resolved. На живой системе ссылку ставит шаг 45; при установке с образа — `05-from-iso` после выхода из chroot; в контейнере не трогается.
- **Телеметрия.**
  - VS Code (stow-пакет `vscode`): `telemetry.telemetryLevel: off`, без экспериментов, онлайн-рекомендаций и онлайн-поиска в настройках.
  - Hyprland: `ecosystem.no_update_news`, `no_donation_nag` (сверено со стабами 0.57.2).
  - pkgstats не ставится, при наличии — предупреждение.
  - Остальной стек телеметрии не имеет, выдуманных переменных не добавлял.
- **AUR.** Список минимальный (bibata, VS Code; yay-bin ставится отдельно). Перед сборкой показывается PKGBUILD каждого пакета с вопросом «собирать?». Флаг `--trust-aur` отключает показ. yay сохранён с `--diffmenu --answerdiff All` — флаги сверены с `yay --help` версии 13.1.0.
- **Сканеры.** clamav, rkhunter, lynis ставятся, службы не включены. Включён только `clamav-freshclam-once.timer` (есть в пакете clamav). Команды ручной проверки — в README.

  - Дампы памяти выключены: `Storage=none`, `ProcessSizeMax=0`.
  - Secure Boot — только по `--secure-boot` (`36-secureboot.sh`, sbctl, ключи Microsoft через `-m`); риск и откат — в README.

**Опционально (по флагам):** `--apparmor-d`, `--secure-boot`, `--trust-aur`.

## Аудит плана (замечания лида) — как закрыты

1. `--from-iso`:
   - отдельная ветка, `install.sh` после неё сразу выходит, внутри chroot запускается обычный `install.sh` без `--from-iso`;
   - повтор предлагает продолжить без разметки (метка `/root/.dots-base-done`);
   - диск принимается только из показанного списка и только несмонтированный;
   - UEFI проверяется; перед стиранием выводится, что будет стёрто и что ставится systemd-boot;
   - запись загрузчика с `rootflags=subvol=@`.
2. Обязательные шаги `00`, `10`, `50`, `55` при ошибке останавливают установку с кодом 1. Если stow упал при первой установке, частичные ссылки убираются, перемещённые конфиги возвращаются.
3. multilib включается в `00-preflight` до `10-base`. Если секции нет совсем (как в docker-образе), она дописывается. Потом `pacman -Syu` с тремя попытками.
4. Службы nvidia-suspend/resume/hibernate больше не включаются. Вместо `/sys` в chroot — проверка `dkms status` для каждого ядра в `/usr/lib/modules`, modeset — после перезагрузки.
5. Бэкап:
   - путь проверяется сверху вниз; папка-ссылка или файл на месте папки уносится целиком, не разыменовывая;
   - при первой установке сохраняются и файлы, которые перезапишут matugen и установщик (qt5ct/qt6ct);
   - `stow -n` не используется: конфликты вычисляются сами, поэтому разбирать его код выхода не нужно;
   - повторный запуск новый бэкап не создаёт (проверяется в тесте).
6. SDDM: `/var/lib/dots-sddm` (не `sddm-matugen`) создаётся шагом 70 с правами 755, файлы 644 — пользователь sddm их читает. `theme.conf.user` — ссылка на INI с цветами. Первая палитра строится без Hyprland, awww и D-Bus: проверено, matugen работает в контейнере без сессии.
7. Перекраска:
   - шаблон qt5ct есть;
   - `QT_QPA_PLATFORMTHEME=qt5ct` — плагин qt6ct понимает это имя, проверено по строкам библиотеки;
   - GTK3 перечитывает тему через переключение `gtk-theme`;
   - `wallpaper-set` под `flock`;
   - начальные обои копируются в `~/Pictures/wallpapers`;
   - свои скрипты вызываются по полному пути.

   Не сделано: атомарная замена файлов (их пишет сам matugen), живое обновление уже открытых Qt-программ — они перекрашиваются после перезапуска.
8. Сессия:
   - в тесте проверяются включённые sddm, NetworkManager, bluetooth, docker, postgresql, nftables, resolved и пользовательские pipewire, pipewire-pulse, wireplumber;
   - polkit-агент и импорт окружения (`dbus-update-activation-environment --systemd`) запускаются в autostart;
   - раскладка us,ru с Alt+Shift.
9. HDMI-звук: ожидание до 10 секунд; уже играющие потоки переносятся; при отключении звук возвращается на прежний выход; вызовы идут по очереди через `flock`. Перед переключением проверяется, что ТВ всё ещё подключён.
10. Решённые вопросы в PLAN.md заменены решениями владельца. Тест пакетов читает списки без комментариев. `Hyprland --verify-config` есть в тестах.

## Финальный аудит (лид): ошибка rsync в `--from-iso` пропускалась

**Находка подтвердилась, и она касалась версии после моей правки.** `run_user_stage` вызывается как `run_user_stage … || status=$?`, а в таком вызове bash отключает `set -e` внутри всей функции. Поэтому при падении `rsync` (код 23) функция шла дальше, дважды вызывала `arch-chroot`, печатала «dotfiles установлены» и возвращала 0.

**Исправлено** (`install.d/05-from-iso.sh`):
- каждое действие в `run_user_stage` проверяется явно: `rsync`, `chown`, запись временного sudoers, сама установка, удаление sudoers;
- при ошибке выводится «Ooops.. …» и функция возвращает ненулевой код: код упавшей установки передаётся как есть;
- временный файл NOPASSWD удаляется в любом случае, метка возобновления остаётся;
- `main` вызывается только при прямом запуске файла, чтобы тест мог подключить его через `source`.

**Тест** `tests/iso-stage-check.sh`: подменённые `rsync` и `arch-chroot`, четыре сценария, 14 проверок, все PASS. Тест встроен в `container-test.sh`.
- `rsync` падает → ненулевой код, «Ooops..», `arch-chroot` не вызывается, сообщения об успехе нет;
- `chown` падает → установка не запускается, файла NOPASSWD нет;
- установка падает с кодом 5 → функция возвращает 5, «Ooops..», NOPASSWD удалён, метка возобновления на месте;
- всё успешно → код 0, NOPASSWD и метка удалены.

Ещё аудит смотрел `50-backup.sh` (`plan_path`, `matugen_outputs`) и `sbctl status`, но выводов не дал. Сам я ошибок там не нашёл: пути matugen берутся из `output_path`, несуществующая промежуточная папка прерывает обход. `--secure-boot` по-прежнему считаю черновым — см. остатки выше.

## Финальный аудит кода (10 пунктов) — как закрыт

Каждую находку сначала проверил сам. Где это можно было сделать без железа — тестом с подменёнными командами (как с rsync). Неверных находок нет: все десять подтвердились.

1. **Возобновление `--from-iso` (блокер) — подтвердилось и исправлено.** Раньше путь возобновления срабатывал, только если `/mnt` остался смонтированным, а после сбоя скрипт сам его размонтировал. Теперь:

## Проверка перед установкой (16.11.2026, вечер)

Вопрос был: можно ли ставить и заработает ли. Полный `bash tests/run.sh` до правок — ALL CHECKS PASSED. Шаг разметки (`wipefs` + `sgdisk --zap-all` + создание разделов) проверен на файле-образе: чистый диск, диск с GPT, диск с MBR — код 0 во всех трёх случаях. Найдено и исправлено:

1. **Параметр AppArmor не попадал в загрузчик на пути archinstall.** `patch_systemd_boot` читал список записей циклом `while read … < <(find)`. Цикл занимал stdin, `ask_exact` видел «нет терминала», печатал «пропускаю», а шаг `38-apparmor` заканчивался успехом. То же с `--bootloader`. Воспроизведено под терминалом: запись не менялась, код 0. Теперь список читается в массив (`lib/bootloader.sh`). Тест: `sed-check.sh` запускает `add_kernel_param` под терминалом (`script`), вводит `yes` и проверяет запись. Путь `--from-iso` не страдал: там параметр пишется сразу.
2. **Звук на телевизор не переключился бы.** `pactl -f json list cards` отдаёт порты карты объектом «имя порта → свойства» (исходник `pactl.c`), а фильтр ждал список с полем `name` и получал имя порта `null`. Подмена pactl в тесте повторяла ту же ошибку, поэтому тест проходил. Теперь имя порта берётся из ключа, подмена приведена к настоящему виду.
3. **Повторный `tv-audio on`** при уже включённом ТВ затирал запомненный выход, и `off` вернул бы звук на сам ТВ. Теперь прежнее состояние не перезаписывается. Тест добавлен.

Проверено и отклонено: «после установки драйвера initramfs не пересобирается, если на оба вопроса шага 30 ответить нет». Хук `90-mkinitcpio-install.hook` срабатывает на `usr/lib/modprobe.d/` и `usr/src/*/dkms.conf`, то есть при установке `nvidia-utils` и `nvidia-open-dkms` initramfs пересобирается сам.

Осталось владельцу:
- **Бит запуска.** Репозиторий лежит на Windows (`core.filemode=false`), коммитов нет. При первом коммите выполнить `git add --chmod=+x install.sh install.d/*.sh scripts/.local/bin/* tests/*.sh`, иначе `./install.sh` на Arch ответит `Permission denied` (обход: `bash install.sh`). Тест этого не видит: он запускает `bash install.sh`.
- В списке пакетов нет браузера и файлового менеджера — поставить после установки (`sudo pacman -S firefox`).
- Синхронизацию времени с 17.11 включает шаг 45 (systemd-timesyncd). Arch держит часы платы в UTC, Windows — в местном времени; если Windows остаётся на втором диске, часы будут расходиться на 5 часов, пока одной из систем не сказать иначе.
